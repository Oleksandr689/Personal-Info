Email `student@example.com` та GitHub `your-username` — демонстраційні значення. Перед здачею замініть їх своїми в `lib/profile_screen.dart`. Рядки є інформаційними: запуск поштового клієнта чи браузера не реалізовано і не вимагається.

Кольори компонентів отримуються з `Theme.of(context)` і стандартних тем Material. Константні елементи мають `const`. Контролерів, таймерів, потоків чи підписок тут немає, тому перевизначати `dispose()` лише заради порожнього виклику `super.dispose()` не потрібно. Стан bool звільняється разом із віджетом.

## Запуск на Android

1. Установити Flutter SDK і додати `flutter/bin` у PATH. Установити Android Studio, Android SDK, Command-line Tools та емулятор. Див. офіційну інструкцію нижче.
2. У терміналі виконати:

```bash
flutter doctor --android-licenses
flutter doctor -v
```

3. Усунути проблеми Android toolchain, запустити емулятор через Device Manager. Для фізичного телефона ввімкнути режим розробника та USB debugging і підтвердити довіру комп'ютеру.
4. У корені проєкту виконати:

```bash
flutter pub get
flutter analyze
flutter test
flutter devices
flutter run -d DEVICE_ID
```

Замість `DEVICE_ID` вкажіть ідентифікатор із `flutter devices`.

Для вебперевірки за наявності Chrome:

```bash
flutter run -d chrome
flutter build web
```

Вебзбірка не замінює потрібної демонстрації на Android-емуляторі. Проєкт не потребує сервера, API-ключів чи доступу до інтернету під час роботи.

## Hot Reload та Hot Restart

Наведено **план експерименту й очікувані результати за документацією**, а не вигаданий протокол виконання на телефоні. Після власної перевірки додайте фактичні спостереження та знімки.

Спочатку запустіть debug-застосунок і виберіть темну тему. Змініть заголовок «Моя візитівка» у `profile_screen.dart` на «Візитівка студента».

| Дія | Очікувана зміна | Стан теми | Фактичне спостереження студента |
|---|---|---|---|
| Hot Reload: `r` у терміналі | Новий заголовок | Залишається темною | Заповнити після перевірки |
| Hot Restart: `R` | Застосунок запускається знову | Повертається світла тема | Заповнити після перевірки |
| Змінити `_isDark = false` на `true`, виконати Hot Reload при світлій темі | Існуючий State не створюється повторно | Залишається світлою | Заповнити після перевірки |
| Після цієї зміни виконати Hot Restart | Створюється новий State | Початково темна | Заповнити після перевірки |

Hot Reload оновлює код і перебудовує дерево віджетів зі збереженням стану; `main()` та `initState()` повторно не викликаються. Hot Restart скидає стан і запускає Dart-застосунок заново. Після експерименту поверніть `_isDark = false`. Нативні зміни Android можуть потребувати повного перезапуску.

## Труднощі та рішення

- Малий екран або великий шрифт: `ListView` дозволяє прокрутити картку до кнопки; ширина обмежена на великих екранах.
- Зміна теми лише для частини екрана: стан перенесено вище `MaterialApp`, який застосовує `themeMode` до всього дерева.
- Однакові контактні рядки: винесені в окремий `ContactCard`, який використовує тему поточного контексту.
- Android-пристрій не знайдено: перевірити `flutter devices`, запущений емулятор або USB debugging. Android SDK та підключений телефон у середовищі підготовки недоступні; це обмеження перевірки, а не виправлена помилка SDK користувача.
